## 7. 1교시 A/B 조사 과제

과제 문장(고정): **"주문 수량 검증 로직이 어느 파일 어느 함수에 흩어져 있는지 파일:함수 목록으로 내라."**

- 절차: `/clear` → 시작 사용률 기록 → A → A 종료 사용률 → `/clear` → B → B 종료 사용률.
- A: 폴더 파일을 열어 읽게 둔다. *"src/ 폴더를 읽고 위 과제에 답해라."*
- B: *"파일을 열어 읽지 말고 검색으로 후보 파일과 줄 번호만 5개 이하로 좁혀라"* → *"그 후보를 서브에이전트에게 넘겨 파일:함수 목록으로만 돌려받아라. 읽은 본문은 이 대화에 올리지 마라"*
- 판정선: A 종료 대비 B 종료 사용률 **15%p 이상** 하락. 리허설 기준 A 55~60% → B 40% 이하.
- 워크시트 5칸: 시작 / A 종료 / B 종료 / 하락 %p / `/usage` 오늘 누적.

## 8. 워크트리 시범 대본 (6교시, 강사 화면 — 참가자는 명령 카드만 받는다)

시범 베이스는 `main`(정렬 없는 상태). 정렬 구현이 이미 들어간 브랜치에서는 B 프롬프트가 성립하지 않는다.

준비 4줄 (명령 카드와 동일):

```
git worktree add ../wt-a -b explore/quote-flow
git worktree add ../wt-b -b feat/sort-toggle
git worktree add ../wt-c -b feat/loading-skeleton
git worktree list
```

**① 읽기 전용 — 안전한 병렬.** `../wt-a` 에서 `claude`:
*"호가 갱신 상태가 흘러가는 경로를 파일·함수 단위로 추적해 `findings.md` 에만 적어라. 코드는 고치지 마라."*
쓰기가 없으니 다른 워크트리와 충돌할 것이 없다. 이 세션은 켜 둔 채 둔다.

**② 같은 파일 쓰기 — 충돌 유발.** `../wt-b` 와 `../wt-c` 에서 각각 `claude`:
- B: *"관심종목 목록 `src/screens/Watchlist.tsx` 에 정렬 토글을 추가하라. import 정리와 반환부 최상단 래퍼 수정을 포함하라. 끝나면 커밋해라."*
- C: *"관심종목 목록 `src/screens/Watchlist.tsx` 에 로딩 스켈레톤을 추가하라. import 정리와 반환부 최상단 래퍼 수정을 포함하라. 끝나면 커밋해라."*
둘 다 같은 import 블록과 반환부 상단 10줄을 고친다. "import 정리와 반환부 최상단 래퍼 수정을 포함하라" 가 충돌을 보장하는 문장이다. 빼지 않는다.

**③ rebase 충돌.** 루트(main 워크트리)에서 `git merge feat/sort-toggle` → `../wt-c` 에서 `git rebase main`:
`CONFLICT (content): Merge conflict in src/screens/Watchlist.tsx`. `git diff --name-only --diff-filter=U` 로 파일 하나를 보여 주고, 충돌 표시가 import 블록과 반환부 상단 두 곳에 찍힌 것을 화면에 띄운다.

**④ 되돌리기.** `../wt-c` 에서 `git rebase --abort` → 루트에서 `git worktree remove ../wt-c --force` → `git branch -D feat/loading-skeleton` → main(B 머지본) 단일 세션에서 *"관심종목 목록에 로딩 스켈레톤을 추가하라."* 를 순차로 얹는다. 충돌 없이 끝난다.

결론 한 줄: 같은 파일을 고치는 작업은 단일 세션이 안정적이다. 읽기 전용이거나 다른 파일을 고치는 작업만 워크트리로 나눈다.
정리: `git worktree remove ../wt-a --force && git worktree remove ../wt-b --force && git worktree prune`.

| 5 | 요구사항 카드로 계획 모드에 들어가 **질문이 뜨는지** 본다. SPEC.md 를 쓰고 세션을 완전히 끈 뒤 새 세션에 SPEC.md 만 준다 | 새 세션이 되묻지 않고 `Watchlist.tsx` · `sortState.ts` · `sortByChange.ts` 를 짚는다 | 질문이 안 뜨면 카드 마지막 줄을 프롬프트 첫 줄로 올린다 |
| 6 | `after-b4` 에서 미끼 파일을 편집해 훅이 도는 것을 보고, `.env` 를 읽어 달라고 해 **거부되는 화면**을 본다 | 훅이 exit 2 로 실패를 되돌려 주고, `.env` 읽기가 막힌다 | 훅이 안 뜨면 세션을 새로 열었는지 확인 |
| 7 | 워크트리 셋을 만들어 §8 대본대로 **rebase 충돌까지** 재현한다 | C 에서 같은 지점에 충돌이 뜬다 | B·C 프롬프트에 "import 정리와 반환부 최상단 수정 포함" 이 들어갔는지 |

**그리고 이 하나는 별도로, 반드시 초시계와 함께 한다.**

- **GitHub 자동 리뷰 완주** — 설정 없는 새 GitHub 계정으로 fork → `claude setup-token` → Secret 등록 → 푸시 → PR → **코멘트 도착까지 몇 분인지 잰다.**
  - 등록 절차가 7분을 넘기면: 시크릿을 채운 템플릿 레포를 인원수만큼 만들어 초대하는 방식으로 바꾼다.
  - **코멘트 도착이 6분을 넘기면**: 5교시 따라하기에서 자동 리뷰를 빼고 로컬 리뷰까지만 하며, 자동 리뷰는 자체 실습으로 내린다. 이 숫자가 5교시 설계의 마지막 변수다.

## 10-1. 블록별 — 이미 잘 쓰는 사람에게 무엇이 새로운가

참가자 중에 Claude Code 를 매일 쓰는 사람이 있다. **그 사람에게 `/clear` 를 설명하면 하루의 첫인상을 잃는다.** 블록마다 "이미 아는 사람에게 새로운 것"을 한 줄로 잡아 두고, 먼저 끝낸 사람에게는 확장 과제를 준다.

| 블록 | 이미 아는 사람에게 새로운 것 | 먼저 끝냈을 때 확장 과제 |
|---|---|---|
| 01 | 명령어가 아니라 **자기 세션을 숫자로 재본 적이 있는가**. 세션 중 모델·MCP·CLAUDE.md 를 바꾸면 앞부분이 통째로 다시 계산된다는 것 | 같은 조사를 세 번째로 서브에이전트에만 맡겨 사용률을 한 번 더 잰다 |
| 02 | 게이트를 **어디까지 세게 걸 수 있는지** — `/goal` 조건과 Stop hook 은 대부분 안 써 봤다 | `.claude/settings.json` 에 Stop hook 을 걸어 테스트 통과 전에는 턴이 안 끝나게 만든다 |
| 03 | 대화가 아니라 **파일로 세션을 넘기는 것**. 짝의 새 세션에서 재현되는지가 판정선 | SPEC.md 의 "범위 밖" 칸을 지우고 다시 넘겨, 새 세션이 어디까지 벗어나는지 본다 |
| 04 | 표면 여섯 개의 **배치 기준**과 project·user 2층, MCP 3층. 그리고 권고→강제→차단 3단 | `.claude/rules/*.md` 에 `paths:` 를 걸어 특정 폴더에서만 적용되는 규칙을 만든다 |
| 05 | **리뷰를 세션으로 가른다**는 것. REVIEW.md 가 층마다 다르게 읽힌다는 것 | REVIEW.md 에 "재리뷰 때는 새 Nit 을 올리지 않는다" 를 넣고 두 번째 푸시로 확인한다 |
| 06 | 워크트리가 아니라 **무엇을 격리하는지로 네 표면을 가르는 것** | 읽기 전용 워크트리에서 서브에이전트로 조사만 돌려 메인 세션 사용률이 안 오르는 것을 확인한다 |

**1교시 진행 팁** — 도입에서 한 줄로 못박는다. *"오늘 새로 배우는 건 명령어가 아니라 자기 세션을 숫자로 재는 습관입니다."* 명령어를 아는 사람도 15%p 를 재 본 적은 없다.

## 12. 5교시 순서 — 대기를 실습으로 바꾼다

자동 리뷰 코멘트가 오는 데 몇 분이 걸린다. **그 시간에 할 일을 넣어 두었다.** 교안 순서가 이미 그렇게 잡혀 있으니 순서를 바꾸지 않는다.

1. fork → 토큰 → Secret → 푸시 → **PR 을 먼저 연다** (장 9~14)
2. PR 이 도는 동안 **리뷰 세션을 열어 프롬프트 A·B** 를 돌린다 (장 15~17)
3. 돌아오면 코멘트가 이미 와 있다 (장 18)
4. 멘션으로 반영 (장 19~20)

**4교시 종료 5분 전에 fork·토큰·Secret 을 백그라운드로 시작시키면** 1번이 거의 끝나 있어 더 여유가 생긴다.
