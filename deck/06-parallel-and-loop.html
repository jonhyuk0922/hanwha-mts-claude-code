리뷰가 보지 못하는 곳에서 하루의 산출물을 팀의 루프로 잇습니다.

이 모듈에서 배울 것

  • 서브에이전트·워크트리·다중 세션·Agent Teams를 무엇을 격리하는지로 가르고, Agent Teams가 사람 협업이 아닌 이유를 짚습니다.
  • 워크트리 둘이 같은 파일을 고치면 어디서 충돌하는지 보고, 그런 작업은 단일 세션이 안정적인 이유를 확인합니다.
  • intent.md에서 인시던트로 돌아오는 루프에 직전 산출물을 얹고, 태스크당 비용 기준선과 지표 5종, 4주 계획을 적습니다.

왜 이걸 하나

앞 다섯 교시는 세션 하나를 다루는 법이었습니다. 이 모듈은 세션을 여럿 돌릴 때의 경계, 태스크 하나의 비용, 결함이 의도로 돌아오는 길을 팀 단위로 붙입니다.

네 표면은 격리하는 것이 다릅니다

무엇을 따로 두는지로 가르면 어느 작업에 어느 표면을 쓸지 정해집니다.

표면격리하는 것같이 쓰는 것잘 맞는 일
서브에이전트컨텍스트세션 · 체크아웃조사·리뷰 같은 읽기 위임 (1교시)
워크트리파일 · 브랜치레포서로 다른 파일을 고치는 두 작업

같은 파일을 고치는 작업 둘은 어느 표면도 안전하지 않아 단일 세션에서 순차로 합니다.

병렬화 표면 · 2/2

Agent Teams는 AI 워커를 조율하는 기능입니다

이렇게 오해합니다

팀원끼리 쓰는 협업 기능

  • 개발자 A와 B의 세션이 서로 대화한다
  • 켜 두면 팀의 작업이 합쳐진다

실제로는

구성원이 전부 AI인 팀

  • 리드 세션 하나가 AI 워커 세션 여럿에 일을 나누고 메일박스로 주고받는다
  • 실험 기능이라 기본은 꺼져 있고, 토큰을 많이 쓴다

📌메모 — Agent Teams는 AI 워커 조율이지 사람 협업의 대체가 아닙니다. 사람 사이의 공유점은 4교시에서 체크인한 레포 설정뿐입니다.

강사 화면 · 1/2

워크트리 셋을 동시에 돌립니다

참가자는 보기만 합니다. 명령 대본은 두 장 뒤에 있습니다.

순서워크트리 · 프롬프트 요지손대는 파일결과
① 읽기 전용A · 호가 갱신 경로를 findings.md에만 적기없음깨끗이 합쳐짐
② 같은 파일 쓰기B 정렬 토글 · C 로딩 스켈레톤, 둘 다 import와 반환부 상단Watchlist.tsx각각은 통과
③ 합치기B를 main에 머지한 뒤 C에서 git rebase main같은 10줄충돌
④ 되돌리기C를 지우고 단일 세션에서 B 위에 순차로—완료

읽기 병렬은 안전하고, 같은 파일 쓰기는 합칠 때 값을 치릅니다.

강사 화면 · 2/2

C에서 rebase 하면 여기서 멈춥니다

assets/images/06-8-worktree-conflict.png 워크트리 C에서 git rebase main 을 친 직후. CONFLICT 줄과 Watchlist.tsx 의 충돌 마커가 함께 보이게 캡처

📌메모 — 되돌리기는 git rebase --abort 뒤 git worktree remove ../wt-c --force, 그리고 단일 세션에서 B 위에 로딩 스켈레톤을 순차로 얹습니다.

명령 대본 · 나중에 직접 해볼 때

워크트리 넉 줄로 시작합니다

브랜치 하나에 폴더 하나를 붙이고, 폴더마다 세션을 따로 엽니다.

레포 루트에서 · 강사 화면과 같은 구성
git worktree add ../wt-a -b demo/findings main
git worktree add ../wt-b -b demo/sort-toggle main
git worktree add ../wt-c -b demo/skeleton main
for d in ../wt-a ../wt-b ../wt-c; do (cd "$d" && npm run setup); done
의미

폴더 셋이 같은 레포의 다른 브랜치를 가리킵니다. 의존성은 폴더마다 따로 깔아야 npm test가 돕니다.

본인 업무

서로 다른 파일을 고치는 작업 둘을 동시에 돌릴 때 이 넉 줄로 시작합니다.

바꿔 끼우는 자리

폴더 이름 wt-a·b·c와 브랜치 이름 demo/*. 끝나면 git worktree remove로 지웁니다.

따라하기 · 1/4

태스크 하나의 비용을 세 단위로 잽니다

개인 Pro/Max에서는 달러가 안 잡히므로 화면에서 읽히는 숫자 셋을 씁니다.

01

컨텍스트 증가분

/context 사용률의 종료값에서 시작값을 뺀 %p

02

왕복 횟수

내가 프롬프트를 보낸 횟수. 확인 한 번도 한 번으로 셉니다

03

소요 분

첫 프롬프트부터 검증 출력이 붙을 때까지

왜 달러가 아닌가

리뷰당 $15~25 같은 금액은 관리형 서비스와 API 과금에만 해당합니다. 대체 단위로 기준선을 잡고, /usage 주간 잔량은 참고값으로만 봅니다.

따라하기 · 2/4

/clear 뒤 시작값부터 적습니다

  1. 01
    시작값을 적는다/clear를 치고 바로 /context. 사용률과 지금 시각을 워크시트 "시작" 칸에 적습니다.
  2. 02
    한 프롬프트로 시작한다다음 장의 프롬프트를 그대로 넣고, 이후 보내는 프롬프트마다 바를 하나씩 긋습니다.
    확인 한 번(y 입력)도 왕복 한 번입니다. 세지 않으면 왕복이 늘어도 모릅니다.
왜

시작값이 없으면 증가분을 계산할 수 없습니다.

assets/images/06-11-context-before-after.png /context 를 시작 직후와 종료 직전에 친 화면 둘. 사용률 숫자가 둘 다 보이게 위아래로 캡처

따라하기 · 3/4

재는 태스크는 내 변경의 회귀 찾기입니다

찾기·재현·수정·검증을 한 프롬프트에 넣어 왕복이 늘어날 자리를 미리 막습니다.

태스크 프롬프트 · 그대로 입력
3교시에서 내가 만든 관심종목 정렬 변경을 after-b2 브랜치와 비교해 회귀를 찾아라.
회귀가 있으면 실패 테스트를 먼저 써서 재현하고, 고친 뒤 npm test 와 npm run typecheck 출력을 붙여라.
없으면 없다고 답하고 돌린 명령과 출력을 붙여라. 확실하지 않은 것은 회귀로 올리지 마라.
의미

2교시의 실패 테스트 선행을 그대로 요구합니다. "없으면 없다"를 허용해 억지 발견을 막습니다.

본인 업무

사내 레포에서 내 커밋 하나를 머지 전에 스스로 점검시킬 때 그대로 씁니다.

바꿔 끼우는 자리

"관심종목 정렬 변경"은 내 커밋 범위로, "after-b2"는 비교 기준 브랜치(보통 main)로 바꿉니다.

따라하기 · 4/4

종료값을 적고 한 줄로 남깁니다

  1. 03
    종료 직전 /context검증 출력이 붙은 직후 /context를 치고 종료값을 적습니다. 종료에서 시작을 뺀 값이 증가분입니다.
  2. 04
    한 줄로 기록한다아래 서식대로 워크시트 기준선 칸에 적습니다. 대괄호 안이 태스크명입니다.
    이 한 줄이 지표 ③이자 4주 뒤 비교의 출발점입니다.
왜

같은 서식이어야 4주 뒤 줄끼리 비교됩니다.

지표 5종

오늘 셋을 재고, 둘은 4주 뒤에 잽니다

④⑤ 칸에는 숫자 대신 측정 원천, 담당자, 첫 집계일을 적습니다.

#지표측정 원천시점
①첫 리뷰까지 걸린 시간PR open → 자동 리뷰 코멘트 (분)오늘
②첫 구현 통과첫 푸시에서 CI green 여부 (O/X)오늘
③완료 태스크당 비용대체 단위 3종 한 줄오늘
④브랜치를 안 건드리고 해결된 코멘트 비율PR 메타데이터 누적4주 뒤
⑤머지 전 잡힌 결함 대 프로덕션 유출인시던트 트래커4주 뒤

①②는 5교시 PR에서, ③은 방금 적은 한 줄에서 옵니다.

4주 계획

실제 레포 한 곳에서 4주 안에 정착시킵니다

담당자 이름은 워크시트 뒷면 표에 적습니다.

주차할 일끝났다는 증거
1주CLAUDE.md와 훅을 실제 레포에 체크인main에 .claude/ 커밋
2주REVIEW.md와 자동 리뷰를 실제 레포 1곳에PR 1건에 자동 코멘트
3주지표 ①②③ 주간 수집 시작세 칸에 주간 숫자
4주④⑤ 원천 연결과 첫 회고담당자가 첫 집계일에 숫자 하나

팀 전체가 아니라 레포 한 곳에서 4주를 채우는 것이 정착의 최소 단위입니다.

자체 실습 · 시작 전 /clear

네 것으로 바꿔 한 번 더

  1. 01
    기준선을 네 태스크로 한 줄 더/clear 뒤 본인이 고른 작은 태스크(5교시 Nit 반영 등)로 같은 절차를 돌려 두 번째 줄을 적습니다.
  2. 02
    지표 다섯 칸을 채운다①②③에 오늘 숫자, ④⑤에 사내 측정 원천·담당자·첫 집계일, 4주 표에 주차별 담당자를 넣습니다.
    짝과 ①②③의 단위를 맞춥니다. 다르면 4주 뒤 비교가 안 됩니다.
왜

기준선은 두 줄부터 비교가 됩니다.

⚠️검증 포인트 — 기준선 한 줄이 대체 단위 3종으로 적혀 있고, 지표 ①②③이 오늘 숫자로 채워져 있으면 통과입니다.

에러 갤러리

막히면 여기부터 봅니다

01

증가분이 음수다

도중에 자동 compact가 돌았습니다. 이번 줄은 왕복과 분만 적고 시작값을 다시 잡습니다.

02

워크트리에서 npm test가 안 돈다

node_modules는 폴더마다 따로입니다. 그 폴더에서 npm run setup을 먼저 돌립니다.

03

④⑤ 칸이 빈다

오늘 숫자가 없는 것이 정상입니다. 측정 원천과 담당자, 첫 집계일 세 개를 적습니다.

💡팁 — 에러는 외우지 않습니다. 메시지를 그대로 Claude에 붙여넣고 왜 그런지, 어떻게 고치는지를 묻습니다.
