계획 분리와 세션 인계

Plan Mode and Session Handoff

Shift+TabCtrl+G요구사항 카드 → SPEC.md세션 완전 종료 후 새 세션짝 판정 3칸

이 모듈에서

계획은 파일로 남기고, 세션은 닫는다

이 모듈에서는 계획 세션과 구현 세션을 갈라 명세 한 장으로 이어 붙입니다.

이 모듈에서 배울 것

  • Shift+Tab으로 읽기만 하는 계획 모드에 들어가고, Ctrl+G로 계획을 직접 고친 뒤 승인합니다.
  • Claude가 먼저 되묻게 해서 SPEC.md를 뽑습니다 — 대상 파일 · 인터페이스 · 범위 밖 · 검증 단계.
  • 계획 세션을 완전히 닫고, 새 세션에는 SPEC.md만 넘겨 구현을 시작하게 합니다.
왜 이걸 하나

계획과 구현을 한 세션에 두면 되묻기 없이 결정이 채워지고, 그 결정은 대화 속에만 남아 옆 사람에게 건너가지 않습니다.

왜 이걸 하나

되묻지 않는 Claude는 임의로 정한다

모호한 요구를 받으면 Claude는 질문 대신 그럴듯한 선택을 하고 구현부터 시작합니다.

01

요구가 비어 있다

"정렬 상태는 유지된다"에 어디에 유지하는지가 없습니다.

02

Claude가 채운다

묻지 않고 localStorage와 절대값 정렬을 고른 뒤 파일을 고칩니다.

03

사람마다 갈린다

같은 카드로 옆 사람은 서버 프로필을 골라 두 구현이 어긋납니다.

📌메모 — 이 모듈의 실습 재료는 관심종목 정렬 기능입니다. 요구사항 카드에 모호한 줄 두 개를 일부러 심어 두었습니다.

계획 생략 기준

한 문장으로 diff를 설명할 수 있으면 생략한다

공식 Best Practices의 기준입니다 — 작은 변경은 계획 없이, 모호하거나 넓으면 계획부터.

작업diff 한 문장판단
오타 · 문구 수정문구 한 줄이 바뀐다생략
로그 한 줄 추가로그 한 줄이 늘어난다생략
변수 · 함수 이름 변경이름만 바뀌고 동작은 같다생략
파일 셋 이상 손대는 기능한 문장이 안 된다계획 모드
되돌리기 어려운 변경한 문장이 안 된다계획 모드
요구가 모호한 신규 기능질문이 먼저 나온다계획 모드

관심종목 정렬은 4번과 6번에 걸려 계획 모드로 갑니다.

requirements-card.md docs/templates/
관심종목 정렬 추가
1. 관심종목 목록 헤더를 눌러 등락률 순으로 정렬한다.
2. 정렬 상태는 화면을 다시 열어도 유지된다.
3. 정렬은 순수 함수 sortByChange 를 거친다.
확정되지 않은 항목은 구현하지 말고 질문으로 먼저 정리한다. 질문은 최대 3개.

  1. 01
    비우고, 모델을 올리고, 두 번 누른다 /clear → /model로 상위 모델 → Shift+Tab 두 번. 하단에 ⏸ plan mode on을 확인합니다. 상위 모델은 계획 세션에서만 씁니다.

  1. 03
    두 질문에 답한다 정답은 없고 결정만 있으면 됩니다. 예를 들어 유지는 localStorage, 등락률은 부호 포함, 거래정지 종목은 맨 아래로 정합니다.

산출물

SPEC.md — 네 칸이 다 차야 인계된다

순서는 SPEC.template.md 그대로입니다. 빈 칸이 곧 새 세션의 질문입니다.

1. 대상 파일경로로
src/screens/Watchlist.tsx · 정렬 상태 보관 모듈(신규) · src/lib/sortByChange.ts
2. 인터페이스이름으로
sortByChange 비교 함수 재사용 · 정렬 상태 읽기 · 쓰기 · 헤더 클릭 핸들러
3. 범위 밖하지 않을 것
서버 저장 · 다른 화면의 정렬 · 거래정지 종목 표시 방식 변경
4. E2E 검증끝에서 확인
npm test → 헤더 클릭 → 새로고침 뒤 유지 → 거래정지 맨 아래

세션을 닫는다

완전히 끄고 새로 켠다

이 모듈에서 "닫는다"는 세션 완전 종료 뒤 새 실행, 하나로 고정합니다.

조작다음 세션에 남는 것이 모듈에서
완전 종료 후 claude 새 실행파일(SPEC.md)뿐인계 실습은 이것 하나
/clear같은 터미널, 이력만 비움정말 끊겼는지 확인이 안 됨
claude --resume대화 전체하루 뒤 같은 작업 재개용

파일로 남길 것은 결정과 범위, 세션으로 이어받을 것은 어제의 내 작업뿐입니다.

강사 화면 ③

질문 없이 파일 셋을 짚는다

새 세션의 첫 응답입니다. 되묻는 줄이 없고 변경 대상이 경로로 적혀 있습니다.

assets/images/03-17-new-session-plan.png 완전 종료 후 새로 실행한 세션에서 프롬프트 C를 넣은 첫 응답 — 질문 0건, 변경 대상 3파일

자체 실습

네 것으로 바꿔 한 번 더

다른 화면의 기능 하나로 같은 루프를 처음부터 돌립니다.

01

카드를 쓴다

주문 폼 수량 프리셋처럼 한 화면짜리 기능을 고르고, 모호한 줄 둘을 일부러 남깁니다.

02

질문 받고 SPEC.md

/clear 뒤 계획 모드에서 답하고, Ctrl+G로 범위 밖과 검증을 채운 뒤 SPEC.md로 씁니다.

03

닫고 새 세션

커밋, /exit, claude, Shift+Tab 두 번, 프롬프트 C. /context 두 값을 적습니다.

⚠️도달 기준 — 새 세션이 되묻지 않고 변경 대상을 경로로 적으면 통과입니다. 관심종목 정렬은 정답 파일 셋을 다 담고 초과가 1개 이하여야 합니다.

짝 판정

옆 사람의 새 세션 화면에 O·X 셋

판정만 하고 고치지 않습니다. X가 나오면 SPEC.md의 빈 칸을 지목하고 끝냅니다.

📌메모 — 하나라도 X면 짝이 SPEC.md 네 칸(대상 파일 · 인터페이스 · 범위 밖 · E2E 검증) 중 빈 칸을 짚습니다. 고치는 것은 이 시간에 하지 않습니다.

막히면

여기서 자주 걸린다

셋 중 하나입니다. 메시지를 외우지 말고 화면 그대로 Claude에 붙여넣습니다.

01

질문 없이 계획으로 간다

계획 모드가 아니거나 카드 끝 줄이 빠진 것입니다. /clear 뒤 Shift+Tab 두 번, 끝 줄을 확인합니다.

02

질문이 넷 이상 온다

"최대 3개" 줄이 빠진 것입니다. "구현에 영향 주는 것만 최대 3개로 다시"라고 되돌립니다.

03

새 세션이 다시 되묻는다

SPEC.md 네 칸 중 하나가 빈 것입니다. "이 질문이 어느 칸에서 왔는지 지목해라"로 칸을 찾습니다.

💡팁 — 되묻는 질문이 곧 SPEC.md의 빈칸 목록입니다. 지우지 말고 칸을 채우는 데 씁니다.
