규칙을 파일로 만들어 레포에 넣습니다

앞 세 교시에서 익힌 세션 규율을 팀 전원의 세션에 같은 방식으로 겁니다.

이 모듈에서 배울 것

  • 각자의 세션은 서로를 모르고 공유점은 레포뿐이니, 통제를 레포 안 설정으로 옮깁니다.
  • /init 초안을 "지우면 실수하나"로 쳐내고 /doctor로 걷어내, 매 세션 로드되는 파일을 200줄 아래로 줄입니다.
  • 규칙을 표면별로 나눠 .claude/에 커밋하고, 같은 프롬프트로 결과가 갈리는지 확인합니다.

왜 이걸 하나 · 1/2

같은 프롬프트를 두 사람이 돌립니다

규칙 없는 레포에서 짝과 각자 돌리고, 결과를 본 뒤 git stash -u 로 치웁니다.

파일 선택을 열어 둔 채 기능 하나를 시킵니다. 마지막 문장이 결과를 갈리게 만드는 장치입니다.

📌메모 — 도구를 몰라서가 아니라 세션마다 규율이 달라서 갈립니다. 이 차이를 리뷰에서 걸러내면 이미 늦습니다.

규칙을 말로 전하면 세션마다 다르게 남습니다. 레포 안 설정에 넣으면 누가 어느 세션을 열어도 같은 규칙이 먼저 로드됩니다.

스코프 · 1/2

팀에 걸 것은 project에만 둡니다

CLAUDE.md와 .claude/는 두 층에 놓일 수 있고, 팀이 보는 것은 한 층뿐입니다.

스코프위치누가 보나무엇을
project./CLAUDE.md · .claude/git 체크인 · 팀 전체팀 규칙 · 훅 · 명령어
user~/.claude/내 컴퓨터만개인 취향

팀원마다 결과가 다르면 대개 누군가의 user 설정이 project와 부딪힌 것입니다.

왜 두 층을 가르나

팀에 걸 규칙이 개인 폴더에 있으면 그 사람 세션에만 걸립니다. project에 있어야 체크인되고 코드처럼 리뷰됩니다.

스코프 · 2/2

MCP 서버는 세 층입니다

충돌하면 좁은 쪽이 이깁니다. local, project, user 순입니다.

스코프위치누가 보나무엇을
MCP local~/.claude.json 의 이 레포 항목나만 · 이 레포개인 토큰이 붙는 서버
MCP project.mcp.jsongit 체크인 · 팀 전체팀이 같이 쓰는 서버
MCP user~/.claude.json나만 · 모든 레포어디서나 쓰는 개인 서버

팀이 같이 쓰는 서버만 .mcp.json 에 커밋하고, 토큰이 붙는 서버는 local에 둡니다.

강사 화면 · 2/2

편집 직후 훅이 돌고 실패가 돌아옵니다

assets/images/04-11-hook-fires.png 미끼 파일 편집 직후 훅 출력(exit 2)과 Claude가 스스로 고치는 두 번째 Edit까지 한 화면에 캡처
왜 이걸 하나

CLAUDE.md는 권고라 지나칠 수 있지만 훅은 매번 돕니다. exit 2로 끝내야 출력이 Claude에게 돌아가고, exit 1은 조용히 지나갑니다.

따라하기 · 1/4

/init 으로 시작해 같은 초안으로 맞춥니다

  1. 01
    /init 실행레포 루트에서 claude 를 열고 /init 을 칩니다. 생성된 CLAUDE.md를 훑습니다.
  2. 02
    초안으로 교체cp docs/templates/CLAUDE.draft.md CLAUDE.md 로 덮어쓰고 wc -l CLAUDE.md 로 180줄을 확인합니다.
    매 세션 전부 로드되는 파일은 이것 하나라, 여기서 줄이는 만큼 모든 세션이 가벼워집니다.
왜 초안으로 바꾸나

/init 결과는 사람마다 달라 짝과 비교할 수 없습니다. 같은 180줄에서 출발해야 지운 줄을 맞춰 볼 수 있습니다.

라벨은 Claude가 달고, 최종 판정과 삭제 승인은 내가 합니다.

프루닝 프롬프트 · 그대로 입력

따라하기 · 4/4

훅 하나를 레포에 체크인합니다 (1/2)

이벤트는 PostToolUse, 대상은 Edit과 Write, 명령은 스크립트 한 줄입니다.

.claude/settings.json
{
  "hooks": {
    "PostToolUse": [{
      "matcher": "Edit|Write",
      "hooks": [{ "type": "command",
                  "command": "\"$CLAUDE_PROJECT_DIR\"/.claude/hooks/check.sh" }]
    }]
  }
}
의미

파일을 고치거나 새로 쓸 때마다 check.sh 를 부릅니다. 검사 내용은 스크립트 안에 가둡니다.

본인 업무

사내 레포에 이 파일을 그대로 커밋하면 팀 전원의 세션에 같은 게이트가 걸립니다.

바꿔 끼우는 자리

없습니다. 경로와 셸 차이를 전부 check.sh 에 넣어 두어야 커밋되는 줄이 모두에게 같습니다.

따라하기 · 4/4

훅 하나를 레포에 체크인합니다 (2/2)

검사 두 개를 돌리고, 하나라도 실패하면 exit 2로 끝냅니다.

.claude/hooks/check.sh
#!/usr/bin/env bash
# Edit|Write 직후 실행. 실패하면 exit 2 → 출력이 Claude에게 돌아간다
cd "$CLAUDE_PROJECT_DIR" || exit 2
if ! (npm run lint -- --quiet && npm run typecheck) 1>&2; then
  exit 2
fi
의미

lint와 typecheck를 차례로 돌립니다. 출력을 stderr로 보내야 exit 2와 함께 Claude에게 전달됩니다.

본인 업무

사내 레포의 검사 명령 두 개를 이 한 줄에 넣으면 그대로 팀 게이트가 됩니다.

바꿔 끼우는 자리

괄호 안의 npm 명령 두 개. 테스트까지 걸려면 npm test 를 뒤에 더합니다.

레포에 놓는 순서

파일 두 개를 놓고 세션을 새로 엽니다

이 모듈이 끝난 레포 · after-b4 브랜치와 같은 상태
hanwha-mts-claude-code/
├── CLAUDE.md                 # 55줄 정본 · 매 세션 로드
├── .claude/
│   ├── settings.json         # 훅 1개 · 팀 공유
│   └── hooks/
│       └── check.sh          # lint + typecheck · 실패 시 exit 2
├── docs/templates/           # 초안·정본·스니펫 원본
└── src/ …
  1. 01
    파일을 놓고 권한을 준다mkdir -p .claude/hooks 뒤 docs/templates/ 의 스니펫과 check.sh 를 위 자리에 복사하고 chmod +x .claude/hooks/check.sh.
  2. 02
    세션을 새로 열어 확인훅은 시작 때 읽힙니다. claude 를 다시 열고 /hooks 에 PostToolUse 가 보이면 됩니다.
    막히면 git checkout after-b4 로 이 상태를 그대로 받습니다.

훅이 도는 장면

미끼 파일을 건드려 훅을 띄웁니다

src/screens/OrderForm.tsx 에는 미사용 import 한 줄과 any 하나가 심겨 있습니다.

템플릿
[파일 경로] 의 컴포넌트 함수 이름을 [새 이름] 으로 바꾸고,
이 파일을 참조하는 곳도 맞춰라. 그 외 줄은 건드리지 마라.
예시 · 그대로 입력
src/screens/OrderForm.tsx 의 컴포넌트 함수 이름을 OrderFormPanel 로 바꾸고,
이 파일을 참조하는 곳도 맞춰라. 그 외 줄은 건드리지 마라.

[ ] 안이 바꿔 끼우는 자리입니다. 이름만 바꾸라고 해도 저장 직후 검사가 돌아 심어 둔 두 문제가 잡힙니다.

⚠️검증 포인트 — 훅 출력이 뜨고 Claude가 미사용 import와 any를 스스로 고치면 통과입니다. 아무 일도 없으면 새 세션인지, exit 2인지 봅니다.

자체 실습 · 시작 전 /clear

네 규칙으로 바꿔 한 번 더

  1. 01
    세 줄을 고쳐 쓴다정본의 세 줄(데이터 페칭 위치 · 네이밍 · 로딩·에러)을 사내 MTS 레포에서 실제로 지키는 규칙으로 바꿉니다.
  2. 02
    커밋하고 짝과 맞춘다git add CLAUDE.md .claude && git commit -m "chore: team config" 뒤 짝과 세 줄을 맞춥니다.
    짝과 다르면 다음 검증에서 그대로 갈립니다.

⚠️검증 포인트 — 두 사람 결과의 데이터 페칭·네이밍이 같고, 근거 줄을 200줄 이하 CLAUDE.md에서 지목하며, 훅이 settings.json에 커밋되어 있으면 통과입니다.

축어디를 보나같아야 하는 것
